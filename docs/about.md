# 关于本项目

## 项目目标
实现从 Markdown 文档到公开静态网站的自动化发布。开发者仅需要专注文档内容的编写与维护，无需手动处理网页编译、文件上传、服务器部署等繁琐操作。当文档内容发生修改时，推送代码即可自动完成站点更新，得到一个拥有固定公网访问地址的在线文档站点，支持持续迭代、多人协作，同时满足课程实验文档展示、技术笔记长期托管的需求。

## 技术组成

| 工具 | 作用 |
| --- | --- |
| Markdown | 轻量标记语言，用来编写文档正文、实验报告，语法简洁，可读性强，兼顾纯文本编辑和网页渲染效果，方便版本管理 |
| MkDocs Material | MkDocs 的热门美化主题，以 MkDocs 为文档构建核心，将 Markdown 源码编译生成带侧边导航、搜索功能、响应式布局的静态网页，统一文档样式 |
| GitHub Actions | GitHub 内置的 CI/CD 自动化流水线工具，监听 main 分支的代码推送事件，按预先编写的配置脚本自动执行依赖安装、文档构建、页面部署等任务 |
| GitHub Pages | GitHub 免费静态网页托管服务，专门存放流水线构建完成的静态网站资源，对外提供稳定、永久的公网访问链接 |
| Git | 版本控制工具，记录每一次文档修改记录，支持回溯历史版本、区分本地与远程仓库，是整个流程的基础 |

## 实现思路
整个项目分为本地开发、版本提交、自动化流水线、线上托管四个阶段。
在本地环境中，使用 Markdown 编写文档，通过 `mkdocs serve` 启动本地服务预览页面效果，提前排查图片路径、导航配置、排版错误等问题；确认内容无误后，借助 Git 对改动文件进行暂存、提交，推送至 GitHub 远程仓库的 main 分支。

代码推送动作会触发仓库内 `.github/workflows/deploy.yml` 定义的 GitHub Actions 工作流。流水线会拉起一个虚拟运行环境，自动安装项目所需 Python 依赖，调用 MkDocs 读取 mkdocs.yml 配置，把所有 Markdown 文档编译为 HTML、CSS、JS 组成的静态站点文件，最后将构建产物上传至 GitHub Pages 对应的部署分支，完成发布。

整套流程打通了“写文档 → 提交代码 → 自动上线”的链路。后续任意修改文档、补充截图、调整导航配置，只要推送到远程仓库，流水线就会重复执行构建部署，网站地址保持不变，访问者打开链接就能看到最新版本内容。
