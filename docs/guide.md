# 使用指南

本指南用于说明如何对当前 MkDocs 文档站点进行内容修改、本地调试、提交发布以及上线验证，适合后续持续维护文档使用。

1. 修改 docs 目录中的 Markdown 文件。
所有正文文档都存放在 `docs/` 目录下，你可以直接编辑已有 `.md` 文件，也可以新建 Markdown 文档；如果需要新增页面，还需要同步在 `mkdocs.yml` 的 `nav` 导航配置中添加对应条目，页面才会出现在网站侧边导航栏。图片等静态资源统一放在指定图片目录，书写时注意文件路径大小写，避免图片加载失败。

2. 在本地预览并检查页面及链接。
修改完成后，优先在本地启动预览服务，**不要直接推送远程仓库**。打开 Git Bash，运行预览命令，在浏览器访问 `http://127.0.0.1:8000`，逐页检查文字排版、图片显示、页面跳转链接、导航菜单是否正常，提前发现语法错误、路径错误、YAML缩进问题。

3. 提交修改并推送到 main 分支。
本地确认效果无误后，使用 Git 命令暂存、提交本次改动，填写清晰的提交备注，说明本次修改内容；再推送到远程仓库的 main 分支。推送动作会作为触发信号，启动 GitHub Actions 的自动化部署流水线。

4. 在 Actions 页面查看构建与部署状态。
推送完成后，进入仓库的 Actions 页面，找到本次触发的工作流记录。观察流水线两个核心步骤：build（文档构建）和 deploy（页面部署）。绿色对勾代表执行成功；如果出现红色失败，点开对应步骤，查看日志定位报错，常见问题包括 YAML 缩进错误、依赖缺失、文件路径错误，修改后重新提交推送即可。

5. 打开网站检查内容是否更新。
流水线全部运行成功后，访问 GitHub Pages 网站地址查看最终效果。如果页面依旧是旧内容，是浏览器缓存导致，使用 `Ctrl + F5` 强制刷新页面。确认文字、图片、导航全部更新成功，本次发布流程结束。

## 常用命令
- `python -m mkdocs serve`：启动本地预览服务，实时监听文件改动，修改md后页面会自动刷新，适合边改边看。
- `python -m mkdocs build --strict`：在本地执行站点构建，`--strict` 代表严格模式，只要出现警告就直接终止构建，可以提前发现文档里的链接失效、引用错误等问题，避免推送到线上后流水线构建失败。
- `git add .`：把当前目录下所有改动文件加入暂存区
- `git commit -m "修改备注"`：保存本次改动，备注写清楚本次更新内容
- `git push origin main`：将本地提交推送到远程main分支，触发自动部署

## 注意事项
1. 不要手动修改自动生成的 `site` 文件夹，该目录是构建产物，每次 build 都会覆盖重写；
2. `.github/workflows/deploy.yml` 是流水线配置文件，若无特殊需求，不要随意改动；
3. Markdown 和 YAML 配置文件缩进必须使用空格，禁止使用 Tab，否则会引发构建报错；
4. 新增图片时，图片路径建议统一、文件名尽量不用中文、空格，减少加载异常。
